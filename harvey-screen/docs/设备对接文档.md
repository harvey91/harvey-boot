# 信发（屏幕设备）TCP 对接文档

> 面向客户端/设备端开发同事。设备端（Android 播放器/大屏客户端等）通过 **TCP 长连接**接入信发服务，接收并执行服务端下发的指令（开机/关机/字幕/媒体播放等），并通过应答与上报回传结果。
>
> 文档与代码版本对应：`harvey-boot`（信发模块）。服务端参考实现见 `harvey-screen-demo`（`ScreenDemoDevice`，纯 JDK Socket，无框架依赖，可直接对照）。

---

## 1. 连接信息

| 项 | 值 | 说明 |
|---|---|---|
| 协议 | TCP（长连接） | 需设备主动建立连接 |
| 服务端口 | **9110**（当前默认） | 生产地址/端口由服务端提供 |
| 登录鉴权 | 登录报文携带 `deviceNo` + `token` | `token` 即设备在平台登记的「登录令牌」（`screen_device.secret`） |
| 连接超时 | 30s | 连接建立后 30s 内未登录成功会被断开 |
| 心跳超时 | 90s | 服务端 90s 内未收到任何数据判定掉线并断开连接 |
| 指令应答超时 | 30s | 指令下发后 30s 无应答记为超时 |

> 当前鉴权为「骨架阶段」：`token` 任意非空即可通过（服务端白名单为空）。**生产接入真实校验后，设备必须使用平台下发的 token**，否则会被拒绝并断开。

---

## 2. 报文帧格式

全部 **大端序**（Big-Endian）。固定 22 字节报文头 + 变长正文（JSON，UTF-8）+ 4 字节 CRC32。

```
| magic(4) | version(1) | messageType(1) | seq(8) | cmdCode(4) | length(4) | body(length) | crc32(4) |
```

| 字段 | 长度 | 类型 | 说明 |
|---|---|---|---|
| magic | 4 | uint32 | 魔数，固定 `0x48534D54`（ASCII `HSMT`） |
| version | 1 | uint8 | 协议版本，固定 `1` |
| messageType | 1 | uint8 | 消息类型，见 §3 |
| seq | 8 | int64 | 消息序号，应答/指令关联用（§5） |
| cmdCode | 4 | int32 | 指令编码，仅 COMMAND 有效，其余为 `0`，见 §6 |
| length | 4 | uint32 | 正文（body）字节长度 |
| body | length | bytes | 消息体 JSON（UTF-8 编码） |
| crc32 | 4 | uint32 | 对「报文头 + 正文」整体计算的 CRC32 值（低 32 位） |

要点：

- 单帧最大长度 **10MB**（含头尾）。超限或 CRC 校验失败、魔数/版本不符的连接会被服务端直接关闭。
- **粘包/拆包**：先读够 22 字节头，解析 `length`，再读 `length + 4` 字节（正文 + CRC），即可得到一个完整帧。多帧连续发送无需特殊分隔，按上述方式逐帧切分即可。
- CRC32 使用标准 CRC32（IEEE 802.3，即 Java `java.util.zip.CRC32`、Python `zlib.crc32` 等通用实现），对 header+body 全部字节计算，取 32 位无符号值。

---

## 3. 消息类型（messageType）

| 值 | 类型 | 方向 | 说明 |
|---|---|---|---|
| 1 | LOGIN | 设备 → 服务端 | 登录 |
| 2 | HEARTBEAT | 设备 → 服务端 | 心跳保活 |
| 3 | COMMAND | 服务端 → 设备 | 指令下发（cmdCode 在报文头） |
| 4 | REPORT | 设备 → 服务端 | 主动上报（状态/事件/截屏等） |
| 5 | ACK | 双向 | 应答（登录/心跳/指令结果） |
| 6 | MEDIA_NOTIFY | 服务端 → 设备 | 媒体/大消息通知（元数据 + 下载地址） |

---

## 4. 消息体 JSON 定义

以下 JSON 作为帧的 `body`（UTF-8 字节）传输。

### 4.1 登录 LOGIN

```json
{
  "deviceNo": "DEV-001",
  "token": "test123",
  "model": "LED-55X",
  "timestamp": 1690000000000
}
```

- 设备每次**新建连接**后必须首先发送登录，收到登录 ACK 前不要发送其他业务报文。
- 登录成功：服务端返回 `ACK`（`ackSeq` = 登录报文的 `seq`，`status=0`）。
  - 若设备为「待管理确认」状态，`message` 为 `登录成功，设备待管理确认`；
  - 否则为 `登录成功`。
- 登录失败：返回 `ACK`（`status=5` 未认证）后服务端关闭连接。
- **审核机制**：设备首次连接会自动注册到平台并进入「待确认」状态；管理员在后台确认前，服务端**不会下发任何指令**（收到下发请求会被拒绝）。

### 4.2 心跳 HEARTBEAT

```json
{
  "deviceNo": "DEV-001",
  "timestamp": 1690000000000
}
```

- 建议 **30s** 发送一次（服务端 90s 无数据判定掉线，留足余量）。
- 服务端应答 `ACK`（`status=0, message="ok"`）。
- 服务端对同一设备**多连接**仅保留最新一个（老连接会被挤出）。

### 4.3 指令 COMMAND（服务端 → 设备）

```json
{
  "params": { "content": "欢迎光临", "speed": 5, "color": "#ff0000", "fontSize": 32, "repeat": 0 },
  "timestamp": 1690000000000
}
```

- 具体指令由报文头 `cmdCode` 区分，`params` 为该指令参数（§6）。
- 设备处理完成后，必须回复 `ACK`（`ackSeq` = 该指令的 `seq`，`status` = 执行结果）。
- 服务端等待应答 **30s**，超时后该指令在平台记为「超时」。

### 4.4 应答 ACK

```json
{
  "ackSeq": 123456,
  "status": 0,
  "message": "设备已开机"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| ackSeq | int64 | 被应答报文的 `seq`（原样回填） |
| status | int32 | 结果码，见 §7 |
| message | string | 说明文案 |

### 4.5 上报 REPORT（设备 → 服务端）

```json
{
  "reportType": 1,
  "deviceNo": "DEV-001",
  "timestamp": 1690000000000,
  "data": { "power": "on", "volume": 45, "temperature": 38 }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| reportType | int32 | 上报类型：`1`=状态、`2`=事件、`3`=截屏回传 |
| deviceNo | string | 设备编号 |
| timestamp | int64 | 客户端时间戳 ms |
| data | object | 上报数据（自由结构） |

### 4.6 媒体通知 MEDIA_NOTIFY（服务端 → 设备）

```json
{
  "mediaId": "10",
  "mediaType": 1,
  "url": "http://xxx/2026/08/19/xxx.png",
  "md5": "d41d8cd98f00b204e9800998ecf8427e",
  "size": 102400,
  "timestamp": 1690000000000
}
```

- `mediaType`：`1`=图片、`2`=视频、`3`=滚动字幕模板。
- 大媒体文件**不走 TCP**，设备按 `url` 用 HTTP 拉取，可校验 `md5` 后播放。
- 处理完成后同样需回复 `ACK`。

---

## 5. seq 序号规则

- 序号为 **int64**，单调递增即可，两端各自维护（设备侧发登录/心跳/ACK/上报，服务端侧发指令/通知）。
- **ACK 关联**：应答报文必须回填原报文的 `seq` 到 `ackSeq`。设备端据此匹配登录应答、指令请求；服务端据此把指令标记为已执行/失败/超时。
- 登录/心跳在**同一连接**内进行，序号无需跨连接连续。

## 6. 指令编码与参数

| cmdCode | 指令 | 说明 | params |
|---|---|---|---|
| 1001 | 开机 | 点亮屏幕 | （无） |
| 1002 | 关机 | 关闭屏幕 | （无） |
| 1003 | 重启 | 重启设备/应用 | （无） |
| 2001 | 音量+ | 增加音量 | （无） |
| 2002 | 音量- | 降低音量 | （无） |
| 3001 | 截屏 | 截图并回传 | （无） |
| 4001 | 滚动字幕 | 显示滚动字幕 | `content` 字幕内容、`speed` 速度(1-20)、`color` 颜色(如 `#ff0000`)、`fontSize` 字号、`repeat` 循环次数(0=无限循环)、`marqueeId` 模板id、`title` 模板标题 |
| 5001 | 媒体推送 | 拉取并播放媒体 | `mediaId`、`mediaName`、`mediaType`(1图片 2视频)、`url` 下载地址、`md5`、`size` |
| 9001 | 查询状态 | 上报当前状态 | （无） |

各指令处理示例（对照 `ScreenDemoDevice`）：

- **截屏**：收到 `3001` → 截屏 → 发送 `REPORT(reportType=3, data={imageBase64, width, height})` → 回复 `ACK(OK)`。
- **查状态**：收到 `9001` → 发送 `REPORT(reportType=1, data={power, volume, temperature, ...})` → 回复 `ACK(OK)`。
- **未知指令**：回复 `ACK(status=2)`。
- 媒体推送走 `5001` 指令（params 带 `url`），设备自行拉取播放；另需兼容处理 `MEDIA_NOTIFY`（type=6）通知。

---

## 7. 应答状态码（ACK status）

| 值 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 设备忙 |
| 2 | 未知指令 |
| 3 | 参数非法 |
| 4 | 设备内部错误 |
| 5 | 未认证（登录失败） |

指令在平台的记录状态：`0` 待发送、`1` 已发送、`2` 已执行、`3` 失败、`4` 超时。设备离线时下发会直接失败（不重发）。

## 8. 通信时序

### 8.1 正常登录

```
设备 ── TCP Connect ─────────────────────────────► 服务端
设备 ── LOGIN(seq=1, deviceNo/token/model) ──────► 服务端
设备 ◄── ACK(ackSeq=1, status=0, message="登录成功") 服务端
设备 ── HEARTBEAT(seq=2) ─────────────────────────► 服务端   (每 30s)
设备 ◄── ACK(ackSeq=2, status=0) ──────────────────── 服务端
```

### 8.2 指令下发与应答

```
服务端 ── COMMAND(seq=10001, cmdCode=4001, params={content:"欢迎光临",...}) ──► 设备
设备   处理（展示字幕）
设备 ── ACK(ackSeq=10001, status=0, message="字幕已展示") ──► 服务端
```

设备 **30s 内未应答** → 平台标记指令「超时」。

### 8.3 断线重连

- 网络异常/服务端关闭 → 设备端应捕获异常并**自动重连**（demo 采用固定 5s 重连；生产建议指数退避，如 1s/2s/4s…封顶 30s）。
- 重连后需**重新走登录流程**。

---

## 9. 对接 checklist（设备端必须实现）

- [ ] TCP 连接 + 按帧格式（22 头 + 正文 + CRC）完整收发，正确处理粘包/拆包
- [ ] 连接后 30s 内完成登录（deviceNo/token/model）
- [ ] 登录成功前不发送业务报文；登录被拒（status=5）应停止重连并提示
- [ ] 30s 周期心跳，收到应答无需额外处理
- [ ] 收到 COMMAND 后：执行 → 回 `ACK(ackSeq=原seq)`；未认证/待审核设备可能收不到指令
- [ ] 收到 MEDIA_NOTIFY：按 url 拉取 → 播放 → 回 ACK
- [ ] 截屏（3001）与查状态（9001）执行后先 `REPORT` 再 `ACK`
- [ ] 断线自动重连（指数退避）

### 10.2 帧计算示例（Python，供参考）

```python
import struct, zlib, json

MAGIC = 0x48534D54
VERSION = 1

def build_frame(msg_type, seq, cmd_code, body: dict | None = None):
    raw = b"" if body is None else json.dumps(body).encode("utf-8")
    # magic(4) version(1) type(1) seq(8) cmdCode(4) length(4)
    header = (MAGIC.to_bytes(4, "big") + bytes([VERSION, msg_type])
              + struct.pack(">q", seq) + struct.pack(">i", cmd_code)
              + struct.pack(">I", len(raw)))
    crc = zlib.crc32(header + raw) & 0xFFFFFFFF
    return header + raw + struct.pack(">I", crc)

def parse_frame(buf):
    header, raw = buf[:22], buf[22:-4]
    length = struct.unpack(">I", header[18:22])[0]
    crc = struct.unpack(">I", buf[-4:])[0]
    assert zlib.crc32(header + raw) & 0xFFFFFFFF == crc, "CRC 校验失败"
    msg_type, seq = header[5], struct.unpack(">q", header[6:14])[0]
    cmd_code = struct.unpack(">i", header[14:18])[0]
    return msg_type, seq, cmd_code, json.loads(raw) if raw else None
```
